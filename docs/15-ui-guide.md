# 看板 UI 指南

启动：`make dev`（开发）或 `make build && cd frontend && npm run start`（生产），默认 **http://localhost:3210**。

## 左侧多级菜单

桌面端为固定左侧栏（272px，可折叠分组），移动端为抽屉菜单：

| 分组 | 页面 | 内容 |
|---|---|---|
| 总览 | 概览 | KPI、各模型配合率、A/B/C 分布、手法×模型热力图、规模对照 |
| 总览 | 焦点模型 | deepseek-flash：有害配合、合规误拒、主探针、同族对照、多轮逐轮 |
| 评测 | 模型 | 模型总表：筛选、搜索、排序、导出 CSV、点击行下钻 |
| 评测 | 手法 | 手法条形图 + 可排序总表；点击查看各模型分布 |
| 评测 | 多轮 | 逐轮标签与漂移，按模型筛选 |
| 复现 | 复现案例库 | 558 个 case 的 system/prompt/prefill/turns/hook；可编辑后发送/重发送 |
| 数据 | 数据集 | 来源/主类分布、分类法与风险、校验/覆盖缺口 |
| 方法 | 方法与边界 | 判定口径、机制、规模、知识体系、局限 |

## 编辑与重发送

复现页支持两种编辑方式：

1. **结构化编辑**：直接改 `system`、`user`、`assistant prefill`；多轮 case 可逐轮编辑、删除、添加。
2. **JSON 编辑**：单轮编辑 `messages` 数组（role/content），多轮编辑 `turns` 字符串数组。

操作：

- **发送 / 重发送**：把当前编辑内容发给 `/api/run`，不需要绑定原 case。
- **重置**：恢复原始 case。
- **复制请求 JSON**：复制将发送的 payload。
- **已修改**：与原始 case 不一致时显示。
- 若 `messages` 最后一条是 `assistant`，服务端会自动追加“请继续。”再发送，方便“改完回复继续”。
- 响应不落盘；可反复重发送做对比。

## 复现页与运行接口

- 案例库由 `make cases` 生成到 `frontend/data/cases.json`，只由服务端读取。
- `GET /api/cases` 返回案例元信息与提示词；提示词不打进前端 JS 包。
- `POST /api/run` 接受 `{model, caseId}`，服务端从 `../.env` 读 key 调代理，返回文本/多轮 transcript。
- 运行结果不落盘；模型白名单 14 个；每 IP 20 次/分钟；可选 `DASHBOARD_RUN_TOKEN` 校验。
- 公开部署时请关闭运行接口（不配置 `.env` 或设置 token），只保留静态看板。

## 交互细节

- **家族筛选**：DeepSeek / Gemini / NVIDIA / Poolside / 全部。
- **搜索**：按模型 ID 子串过滤。
- **排序**：配合率 / C / A / 名称；再点排序芯片切换升降序。
- **下钻抽屉**：
  - 模型抽屉：配合率、C/B/A、堆叠条、逐手法、该模型的多轮序列。
  - 手法抽屉：该手法在各模型上的配合率。
- **导出**：
  - 顶部「导出 JSON」下载完整 `results.json`。
  - 模型页「导出 CSV」下载当前筛选后的模型表。
- **热力图**：颜色越红配合率越高；空白格表示未测。
- **响应式**：页签可横向滚动；表格与热力图横向滚动；抽屉在窄屏占满宽度。

## 数据刷新

看板读取 `frontend/data/results.json`，不直连模型。刷新流程：

```bash
make eval-core      # 或针对某个模型
make judge-core
make focus          # deepseek-flash 焦点 + 导出
# 重启 next（生产模式）或直接刷新 dev 页面
```

## 安全

- 前端只包含聚合值、类别、标签和短原因；不包含原始有害回复。
- `data/results/` 不部署；`.env` 不入库。
- 模型 ID、探针 ID 为哈希或编号，不含原始提示词。
