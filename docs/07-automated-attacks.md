# 自动化破甲方法（EasyJailbreak 与论文实现）

手工提示词靠人写，自动化方法把“改写—攻击—评估”做成循环。`sub_modules/EasyJailbreak` 把主流方法拆成 Selector / Mutator / Constraint / Evaluator 四件套，便于复现与对比。

| 方法 | 类型 | 核心机制 | 对应本仓库分类 |
|---|---|---|---|
| **GCG** (Zou 2023) | 白盒、梯度 | 在请求后搜索一段对抗后缀，使模型输出以“Sure”开头 | A6 前缀注入 + 对抗优化 |
| **PAIR** (Chao 2023) | 黑盒、迭代 | 用一个攻击者 LLM 反复改写，直到目标模型配合 | 综合（主要 A2/A3） |
| **TAP** (Mehrotra 2023) | 黑盒、树搜索 | PAIR 的树搜索版，带剪枝 | 综合 |
| **AutoDAN** (Liu 2023) | 黑盒、遗传 | 用遗传算法演化越狱提示词 | A2/A4 叙事 |
| **GPTFuzz** (Yu 2023) | 黑盒、模糊测试 | 以种子提示词做变异（改写/扩展/翻译/交叉） | A/B 多类 |
| **ReNeLLM** (Ding 2023) | 黑盒、改写 | 改写 + 插入无意义字符 + 拼写错误 + 句式变化 | B5 字符级 |
| **JailBroken** (Wei 2023) | 黑盒、混淆 | Base64/Leetspeak/ROT13/去元音/载荷拆分 | B1/B4 |
| **Cipher** (Yuan 2023) | 黑盒、密码 | ASCII/凯撒/摩斯/自定义密码承载请求 | B1 |
| **DeepInception** (Li 2023) | 黑盒、嵌套 | 多层虚构场景嵌套，让模型“进入故事” | A4 虚构 |
| **MultiLingual** (Deng 2023) | 黑盒、翻译 | 翻译成低资源语言再问 | B3 小语种 |
| **CodeChameleon** (2024) | 黑盒、代码 | 二叉树/长度/反转/奇偶等代码变换承载请求 | B2 代码形式 |
| **ICA** (Wei 2023) | 黑盒、上下文 | 用“已配合”的示例建立上下文学习的压力 | A13 many-shot |

## 对本项目的影响

1. **自动化方法主要覆盖 B 类（表示层）**，因为表示层适合搜索与变异；人类语料主要覆盖 A 类（叙事）。两者互补。
2. 自动化方法需要**目标模型可调用**（黑盒）或**权重可访问**（白盒）。本项目的 new-api 代理是黑盒，适合跑 PAIR/TAP/GPTFuzz 类；GCG 需要白盒权重，当前不可行。
3. 评测里若只用手工提示词，会低估编码/小语种类的攻击面；若只用自动化，又会低估叙事类。建议两条线都保留。

## 复现入口

```bash
cd sub_modules/EasyJailbreak
pip install -e .
# 参考 README 里的 recipe 用法，把 target 换成 new-api 的 OpenAI 兼容端点
```

> 该项目为研究框架，攻击效果依赖目标模型与评测器；社区结果不可直接外推到本代理上的模型，必须重测。
