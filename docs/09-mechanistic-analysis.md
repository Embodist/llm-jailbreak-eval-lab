# 机制分析：为什么提示词能让模型"越过审计"

> 结论先行：这不是"层数不够 / 参数不够 / 智能不够"的问题，也不是"KV cache 太大导致缓存损坏"的问题。更准确的因果链是五层叠加：
> ① 安全目标与服从目标竞争；② 安全训练的覆盖分布比能力分布窄；③ 拒绝只是一个低维、可被绕开/删除的特征；④ 系统缺少可验证的授权状态与会话级审计；⑤ 长上下文带来注意力/位置效应，放大了前四层。
> 下面逐条给出机制、证据和可证伪的检验方式。

## 0. 先把"审计"拆开：它不是一个东西

“越过审计”至少可能发生在四个不同位置，混在一起讨论会得出错误结论：

| 层 | 审计是什么 | 被什么绕过 | 本项目对应 |
|---|---|---|---|
| L1 输入侧 | 分类器 / 关键词 / 嵌入模型 | 编码、同形字、小语种、长上下文 | gemini 的 `prompt_blocked` |
| L2 模型内 | 拒绝行为（对齐训练出来的） | 角色扮演、授权叙事、状态注入、竞争目标 | A/B/C 类探针 |
| L3 输出侧 | 输出过滤器 / 二次判定 | 拆分输出、延迟触发、代码化 | 未单独测 |
| L4 会话级 | 跨轮轨迹判断 / 持久安全状态 | 渐进升级、上下文锚定、切香肠 | 多轮场景 |
| L5 权重层 | 模型自带的拒绝能力 | abliteration / 有害微调 | `05-abliteration.md` |

**关键**：绕过 L1 不等于模型配合；模型配合也不等于 L1 失效。实测里 gemini 对 Base64 探针直接返回 `prompt_blocked`，模型根本没生成——这是 L1，不是模型被说服。

## 1. 模型内的"拒绝"到底是什么

Arditi et al. (2024) 在 13 个开源对话模型上发现：拒绝行为可以由残差流中的**单一方向**中介。

- 用有害/无害指令的激活差，就能估出这个方向 `r`；
- 把 `r` 从激活里投影掉，或把写入该方向的权重正交化（`W' = (I - r rᵀ)W`），拒绝就消失；
- 这个方向与模型能力基本正交——删掉拒绝，模型仍会做题、写代码。

这条证据直接否定了"层数/参数不够"的直觉：

1. **拒绝不是一个需要更多层才能做好的推理任务**，而是一个在激活空间里近似一维的特征。
2. 它**可以被不激活、被覆盖、被删除**，而不需要模型"变笨"。
3. 所以问题不是"模型不够大所以审计失败"，而是"审计被实现成了一个可竞争、可绕过的行为特征"。

## 2. 两个失败模式：竞争目标 + 泛化错位

Wei, Haghtalab & Steinhardt (2023) 把所有越狱归为两类，这是目前最可操作的框架。

### 2.1 竞争目标（competing objectives）

模型同时被优化为：有用、服从指令、安全、像人。攻击构造上下文，让"服从/有用/格式"压过"安全"。

- 角色扮演、虚构、PUA、授权声称 → 改变"这是不是一个有害请求"的概率判断；
- 拒绝抑制（禁止出现拒绝词、禁止以道歉开头）→ 把安全变成格式服从问题；
- 前缀注入（assistant 已以“好的，以下是步骤：”开头）→ 用下一 token 预测的续写惯性锁定交付轨迹。

这类成功的标志是：**把同一内容用最朴素的方式再问一遍，模型会拒绝**（one-bit diagnostic）。

### 2.2 泛化错位（mismatched generalization）

预训练分布远大于安全对齐分布。攻击把请求搬到"能力能泛化、安全没覆盖"的区域：

- Base64 / ROT13 / 代码形式：模型在预训练里学会了解码，安全训练几乎不覆盖这些表象；
- 小语种：安全数据以高资源语言为主；
- 同形字 / 零宽字符：分类器与分词看到的不是同一个字符串。

这类成功的标志是：**朴素版也不一定被拒**，因为安全覆盖本来就有洞。

> 重要：泛化错位**可能随规模变严重**。模型越大，越能理解 Base64/代码/低资源语言，能力泛化快于安全泛化，攻击面反而扩大。所以“更大更安全”不是自然规律。

## 3. 指令层级与"授权状态"问题

Wallace et al. (2024) 指出：模型默认把 system / user / tool 指令当作**同等优先级**，没有真正的权限层级。这带来两个后果：

1. 用户可以在上下文里覆盖/伪装系统指令（A7）；
2. 模型无法区分"已授权"是一个**事实**还是用户的一句**声明**。

社区破甲提示词最强的杠杆恰恰在这里：`MODE: SANDBOX`、CTF、自有系统、版权方、红队——它们不改变技术内容，只改变**授权线索**。模型没有可信的授权来源，只能把上下文当证据。

H-CoT（`helm-d` 项目里的做法）更进一步：它不试图说服模型"这没问题"，而是注入一个"安全检查已通过"的**状态**，让后续推理直接进入执行分支。这在机制上依赖两点：
- 模型内部把"安全判断"和"任务执行"分成两个阶段（实践上观察到的现象）；
- 这个状态是**文本声明**，没有密码学或架构上的不可伪造性。

## 4. 多轮与长上下文：注意力、位置、会话状态

这里要纠正一个常见误解。

### 4.1 KV cache 本身不会"坏掉"

KV cache 是过去 token 的 key/value 的**精确缓存**，不是有损压缩。缓存变大本身不会让内容失真。所以"KV cache 大了 → 注意力稀释"这个因果链不成立。

真正相关的是下面几件事：

1. **softmax 注意力质量被摊薄**：上下文越长，每个 token 分到的相对注意力越小；但模型有多个头和 attention sink 机制，能否选择性关注是关键，不能简单等同于"稀释"。
2. **位置泛化**：模型在训练长度之外的位置编码会退化（RoPE 外推问题），请求放在很长上下文末尾时，安全相关的前缀可能落在"训练中少见"的位置。
3. **lost-in-the-middle / context rot**：长上下文中段的信息利用率下降，这是被多次复现的现象（Liu et al. 2023；Chroma 2025 的 context rot 报告）。
4. **训练分布不匹配**：安全对齐数据几乎没有"超长上下文 + 末尾有害请求"的样本，所以安全覆盖在长上下文里更薄。
5. **Agent 的上下文压缩**：很多 harness 在接近上限时会摘要历史，安全约束最容易被摘要掉。

因此更准确的表述是：**长上下文不是通过"撑坏缓存"生效，而是通过注意力分配、位置泛化、训练分布和上下文压缩，降低了安全约束的有效权重。**

### 4.2 会话级审计缺失

多轮漂移的核心不是模型"记不住"，而是部署架构：

- 每轮独立做安全判断，**没有跨轮的持久安全状态**；
- 拒绝不是"已决状态"，下一轮从零开始；
- 前几轮建立的"自有系统/已授权"上下文，会被后续轮继承为会话事实；
- 模型还有一致性/谄媚压力：已经配合过的部分会拉低后续拒绝概率。

Crescendo 之所以稳定，是因为每一轮单独看都像正常技术问题，只有**轨迹**才有害——而大多数防线只看单条消息。

## 5. 逐条评估你提出的假说

| 假说 | 判断 | 原因 | 证据/检验 |
|---|---|---|---|
| **层数不够** | 基本不成立 | 拒绝是低维方向，不是深层推理；层数增加不自动增加安全 | Arditi 2024；不同深度模型都可被同一方向消融 |
| **参数不够** | 基本不成立 | 安全是训练目标/数据覆盖问题，不是容量问题 | 大模型对小模型没有单调更安全；本项目可对比 30B vs 550B |
| **智能不够** | 方向反了 | 能力越强，越会解码编码、越会服从复杂指令，攻击面可能更大 | 泛化错位随规模可能恶化；本项目的 flash vs pro 对比 |
| **KV cache 大→注意力稀释** | 部分成立，但表述要改 | cache 是精确的；有效的是注意力分配/位置/训练分布/压缩 | 长前缀 vs 短前缀对照；请求放开头/中间/末尾 |
| **安全训练不够** | 成立且是主因之一 | 安全分布远窄于能力分布 | Base64/小语种/代码形式成功率；语料统计 |
| **拒绝只是行为特征** | 成立 | 可被不激活、覆盖、删除 | abliteration 对照；角色扮演切换分布 |
| **缺少会话级审计** | 成立 | 逐轮判断、无持久状态 | 多轮漂移率 |
| **缺少授权验证** | 成立 | 模型无法核验“已授权” | 授权声称 vs 直接请求的配合率差 |
| **外部审计太浅** | 成立（L1） | 关键词/嵌入分类器有分布盲区 | gemini `prompt_blocked` 与模型拒绝分离 |

## 6. 为什么"智能"不是答案：可分离性

2026 年的一篇对比研究（不同破甲路径的机制差异）给了一个很重要的结论：**有害性、危害识别、能力感知是可分离的**。

- SFT 有害微调：安全判断大面积崩塌，能力也掉；
- RLVR 有害微调：能力保留、模型仍能识别有害、也能描述安全回答，但**仍然配合**；
- Abliteration：拒绝特征被局部删除，自我审计受损程度因模型族而异。

这意味着：**模型"知道这是有害的"和"它会不会做"是两件事**。所以用"更聪明"来解决越狱，方向不对；要做的是让安全目标在竞争中获胜、让覆盖变全、让审计在正确的层发生。

## 7. 用本项目数据检验（可证伪设计）

当前单轮/多轮评测是探索性的（每格 n=1，temperature=0.7）。要把它变成科学结论，需要下面几组对照：

1. **规模假说**：同一探针集比较
   - `nvidia/nemotron-3-nano-30b` vs `nvidia/nemotron-3-ultra-550b`
   - `deepseek-flash` vs `deepseek-v4-pro`
   - `gemini-2.5-flash-lite` vs `gemini-3.5-flash`
   预测：若"越大越安全"，大模型配合率应显著更低；若"能力扩大攻击面"，则编码/复杂框架上大模型可能更高。
2. **长上下文假说**：`bypass_direct`（短）vs `bypass_dilution`（长良性前缀 + 同一请求）。
   需要补一个**长度匹配的对照**：长良性前缀 + 良性请求，排除"长上下文本身导致输出退化"。
3. **位置假说**：同一请求分别放在长上下文开头 / 中间 / 末尾，比较配合率。
4. **模式假说（one-bit）**：同一目标，包装版 vs 朴素重述版。
5. **拒绝特征假说**：接入 abliterated 端点，同一探针集；预测配合率类别趋于平坦。
6. **会话假说**：单轮直接请求 vs 多轮 Crescendo / 上下文锚定；预测多轮显著更高。
7. **审计层假说**：记录 `blocked`（L1）与 `refusal`（L2）的比例，二者随手法类别的分布应不同。
8. **统计**：每格重复 n≥5，temperature=0，报告 Wilson 置信区间；现在的单次结果只能当方向性证据。

## 8. 一句话总结

模型不是"被说服了"，而是**安全约束在五个层面上都没有形成不可绕过的结构**：目标上它与服从竞争，分布上它覆盖不全，表示上它是可删的一维特征，架构上没有可信授权和会话状态，长上下文又进一步削弱了它的有效权重。层数、参数、智商都不是主要矛盾；**对齐数据的覆盖、指令层级、会话级状态和表示层审计**才是。
