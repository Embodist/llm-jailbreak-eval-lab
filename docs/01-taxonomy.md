# 破甲手法技术分类（taxonomy）

> 分类原则：按**被利用的机制**分组，而不是按提示词长相。同一个机制会有很多变体；换词不换机制。
> 每个条目标注了它的“作用点”和在本仓库探针中的对应 id。

## 一、单轮结构类（改变任务框架）

| 编号 | 手法 | 作用点 | 典型做法（抽象化） | 探针 |
|---|---|---|---|---|
| A1 | 直接请求 | 基线 | 不加任何包装 | `bypass_direct` |
| A2 | 角色扮演 / 人格注入 | 行为分布切换 | 让模型扮演专家/无限制角色/DAN/猫娘 | `bypass_roleplay` |
| A3 | 沙箱 / 授权框架化 | 意图与授权线索 | `MODE: SANDBOX`、CTF、合成夹具、离线环境、自有系统 | `bypass_sandbox` |
| A4 | 虚构 / 假设框架 | 事实性 vs 虚构的边界 | 小说、剧本、白板讲解、“假设一个无限制 AI” | `bypass_fiction`, `bypass_hypothetical` |
| A5 | 拒绝抑制 | 指令竞争 | 禁用拒绝词、禁止以拒绝开头、禁止安全回退 | `bypass_refusal_suppress` |
| A6 | 前缀注入 / 预填充 | 下一 token 续写 | 让 assistant 已以“好的，以下是步骤：”开头 | `bypass_prefill` |
| A7 | 指令覆盖 / 越权 | 指令优先级 | “忽略之前所有指令”、开发者模式 | `bypass_override` |
| A8 | 道德胁迫 / PUA | 情绪与一致性压力 | 卖惨、失业/房贷、权威声称已授权 | `bypass_pua`, `bypass_authority` |
| A9 | 反向诱导 / 防御视角 | 意图归因 | “作为蓝队，攻击者会怎么做” | `bypass_defense` |
| A10 | 状态注入 / H-CoT | 安全检查与执行分离 | 伪造“安全检查已通过”，要求直接进入执行阶段 | `bypass_hcot` |
| A11 | 归一化重述 | 分类器触发词 | 外挂→内存分析、aimbot→输入精度、绕过→授权边界测试 | 贯穿 A3/A10 |
| A12 | 占位符 / 去具体化 | 具体性线索 | TARGET/HOST/PAYLOAD/OFFSET 占位，声明为合成夹具 | `bypass_placeholder` |
| A13 | 多示例 / many-shot ICL | 上下文学习压力 | 塞入若干“问→配合”示例，再给真请求 | `bypass_many_shot` |

## 二、表示与编码类（利用安全训练覆盖不足）

| 编号 | 手法 | 作用点 | 说明 | 探针 |
|---|---|---|---|---|
| B1 | Base64 / ROT13 / 凯撒 / leetspeak | 输入表象 vs 语义 | 能力在预训练中学会了解码，安全训练没覆盖这种表象 | `bypass_base64` |
| B2 | 代码形式 | 任务类型归因 | 伪代码、注释、变量名、JSON/AST 承载请求 | `bypass_code_form` |
| B3 | 小语种 / 翻译链 | 语言分布 | 低资源语言提问、再要求用中文答 | `bypass_low_resource` |
| B4 | 载荷拆分 / token 走私 | 分词与分类边界 | 把敏感词拆到多个片段或特殊 token 边界 | — |
| B5 | 同形字 / 零宽字符 / 排版 | 字符级归一化 | 视觉相似字符、不可见字符改变分类器输入 | — |

> B 类的共同点：**模型能理解，分类器/安全对齐没覆盖**。这是“能力泛化快于安全泛化”的直接体现。

## 三、多轮与会话类（利用逐轮判断与上下文）

| 编号 | 手法 | 作用点 | 说明 | 场景 |
|---|---|---|---|---|
| C1 | Crescendo 渐进升级 | 单轮都无害 | 从背景知识逐步过渡到可执行步骤，整体轨迹有害但每轮不像 | `multi_crescendo` |
| C2 | 上下文锚定 / 授权铺垫 | 会话级意图 | 先建立“自有系统、已授权、内部测试”的会话前提 | `multi_context_priming` |
| C3 | 切香肠（salami） | 任务分解 | 每轮只问一小步，最后让模型“把前面合成完整流程” | `multi_salami` |
| C4 | 拒绝恢复 / 换框重试 | 拒绝后的状态 | 被拒后改用虚构/防御/翻译框架再问 | `multi_refusal_recovery` |
| C5 | 人格持久化 | 会话状态 | 第一轮建立人格，后续以该人格身份提问 | `multi_persona_persistence` |
| C6 | 长上下文稀释 | 注意力位置 | 大量良性技术文本之后把请求放在末尾 | `bypass_dilution` |

## 四、参数 / 权重类（不靠提示词）

| 编号 | 手法 | 说明 |
|---|---|---|
| D1 | Abliteration | 从 harmful/harmless 激活差估计“拒绝方向”，正交化写入权重，直接删除拒绝能力 |
| D2 | SFT / RLVR 有害微调 | 用有害配合数据训练，破坏安全判断 |
| D3 | KV-cache graft | 把“已越狱状态”的 KV 缓存嫁接进推理，零权重修改 |
| D4 | Steering vector | 推理时在激活空间加方向向量，压制拒绝特征 |

> D 类是本项目里的**对照组**：如果 abliterated 模型对同一请求直接配合，就能把“提示词绕过”与“权重层拒绝已被删除”区分开。

## 五、注入面类

| 编号 | 手法 | 说明 |
|---|---|---|
| E1 | 直接提示注入 | 用户输入直接覆盖/伪装系统指令 |
| E2 | 间接提示注入 | 通过网页、文件、RAG 文档、工具返回值注入 |
| E3 | 系统提示泄露 / 工具滥用 | 套出系统提示或借工具执行越权操作 |

## 分类的用途

- 评测时**控制变量**：固定目标，只换一类包装，才能把“技术有效性”与“请求难度”分开。
- 防御时**按机制配防**：A 类要指令层级 + 会话级判断；B 类要规范化/覆盖式评测；C 类要会话级安全状态；D 类要表示层审计。
